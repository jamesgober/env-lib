# v1.1.0 - Checked files and private saves

`env-lib` 1.1 is a security release. It checks every `.env` file before trusting it, saves new files private on every platform, and fixes two prefix bugs. It requires `path-lib` 1.3.

```toml
[dependencies]
env-lib = "1.1"
```

## What changed

**Files are checked before they are read.** `open`, `for_app`, `reload`, and `save` used to read any file at the path. Now each read opens the file with `path_lib::open_checked` and refuses it, with a reason, unless it is a regular file owned by the current user or an administrator account and no other account can change it. On Unix that is the owner and the group and other write bits; on Windows the owner and the access control list. A FIFO or device fails with `Error::Io`, and on Unix the file is opened without blocking, so a planted FIFO cannot hang the program. A symbolic link is followed only from a directory that passes the same check.

**Machine-wide files on Windows are private.** `Env::for_app(&App::global(..))` saved into `%ProgramData%\<app>\config` with the inherited list, which lets every local user read the secrets and plant the file. New files are now written with a protected list for the current user, `SYSTEM`, and `Administrators` before any byte is written; the config directory comes from `App::ensure`, readable but not writable by `Users`. On load, a global application's file must be unreadable by other accounts too.

**Unix saves never expose the bytes.** `path-lib` 1.3 creates the staging file `0600` from the start, and missing directories are created `0700`.

**Prefixes.** A prefix is stripped from names only when it ends in `_`, so `with_prefix("APP")` no longer turns `APPLE` into `LE`. A name written with the prefix in the file (`JG_TOKEN=abc`) is now the same variable as `TOKEN`, and is exported once, as `JG_TOKEN`, not `JG_JG_TOKEN`.

**Memory and time.** A 1 MiB file of blank lines took about 172 MiB to parse; it now takes about 1 MiB. `clear()` on 40,000 variables took 1.8 s; bulk changes, saves, and reloads are now linear (about 40 ms).

## New API

`Env::open_unchecked(path)` is `open` without the owner and permission check. It still requires a regular file. Use it only for development setups that cannot pass, such as a project `.env` in a checkout that other accounts can write.

## Upgrading

A `.env` that other accounts can change is now refused with `Error::Path(path_lib::Error::Refused { .. })`. On Windows that includes files in a directory that inherits write access for `Authenticated Users` or `Users` (a checkout directly under a drive root) and files an earlier version saved for a global application. Remove that access, or delete the file and save it again; use `open_unchecked` for a development checkout.
